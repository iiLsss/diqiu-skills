# 互动知识讲解

把一个知识点变成能亲手操作、可持续修改的本地讲解。以学习者能看懂「改了什么、为什么变化」为目标；界面和互动根据主题设计，不把所有主题套成滑杆或同一种图形。

本 Skill 可由支持 `SKILL.md` 的编程助手使用。`<skill-dir>` 指本文件所在目录；使用该目录下的资源路径，不依赖客户端名称或当前工作目录。前端提示中的“当前编程助手”指正在执行任务的客户端。

## 新建作品

明确知识点、学习对象和希望理解的关系。已有信息足够就采用合理默认；只有影响讲解语义的缺失信息才询问。先做一个能验证核心关系的闭环。

- 根据主题核对知识依据，优先官方教育、教材、科研或专业机构资料，在项目中留下来源及模型边界。公式模型注明单位与假设；定性示意明确不可当成实测时间、倍数或预测。
- 选择能表达关系的互动：参数变化、单因素对照、拆分组合、排序/匹配、过程探索等。对照保持其他条件一致；比较份额保持同样大小的整体。更多取舍见 [互动设计](references/interaction-design.md)，需要时再读。
- 默认采用随附的独立 Node.js 20+ 模板，无需安装 npm 包。在用户指定位置或现有项目内生成；不要在 Skill 目录内生成用户项目：

```sh
python3 <skill-dir>/scripts/init_demo.py <output-dir>
```

初始化仅复制源码。内置「匀速行走」是可运行的适配范例，不能仅改标题便当作新主题完成。按 [模板契约](references/template-contract.md) 替换知识内容、纯函数模型、观察参数、图形和预测题。保持主题模型与 UI、批注 view 的校验及文字说明一致。

先编辑 `data/lesson.json` 与 `web/`，再在生成目录运行：

```sh
node scripts/lab.mjs new demo
node --test tests/*.test.mjs
node scripts/lab.mjs studio demo --port <available-port>
```

选择空闲端口，服务只监听本机；端口被占用时不结束其他项目的进程。若用户现有项目采用其他技术栈，沿用其实现并保留同样的反馈语义，不强制迁移模板。

## 编辑与批注

讲解区块使用稳定 ID。模板有 intro、experiment、why、challenge、limits 五段；这是模板的存储契约，不是所有作品必须长成的视觉结构。实验对象使用主题自己的 anchor 和观察参数，批注保存原文快照。

- 用户可直接编辑某段文字，或留下意见让 当前编程助手 修改。保存批注不会自行启动模型，应清楚告诉用户回到当前对话交代处理。
- 处理批注前，读 [改稿命令与冲突处理](references/feedback-workflow.md)。按 anchor、view、原文和当前内容定位，只修改对应范围；用户明确要求的行为或图形变化在源码中实现。
- 保留 revision、历史、冲突保护、保存中继续输入的草稿，以及迟到响应不可回退版本的规则。完整备份包含整个 demo 目录及 `.history/`；JSON 导出只有内容、批注及历史索引，不能宣传为完整备份。

## 验证与交付

验证核心知识关系及边界，替换范例模型测试为当前主题的测试。浏览器实际操作关键控件，确认数字、形状、单位与说明一致；如有预测环节，答案验证前不泄露，改参数后清除旧结果。

在临时项目中验证「保存批注 → 读取位置/观察参数/原文 → 定点修改 → 刷新保留 → 导出」，并检查手机布局和控制台。不要把验收批注写入用户正在看的正式项目。优先使用环境可用的浏览器/测试工具；没有浏览器时明确未做界面验收，不用单元测试代替。

交付实际运行地址、项目位置、已验范围和必要限制。保留启动命令与知识依据在生成项目中，让项目脱离 Skill 所在机器也可运行。只有用户要求时才公开部署。
